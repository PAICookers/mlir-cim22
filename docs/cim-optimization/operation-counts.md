# CIM 计数口径与基准结果

## 计数口径

分别统计发送批次、USB 协议记录、响应包和固定等待。一个发送批次可封装多条协议记录，USB bulk transfer 也可携带多条记录。各层计数分别用于分析主机调度、链路流量和板卡等待。

### 发送与接收计数

一条 USB record 为 12 字节，包含 4 字节桥接头和 8 字节 CIM flit。桥接头记录物理链路和逻辑通道。一个输出 Cache 响应包包含 1 条头 flit 和 6 条正文 flit，合计 7 条 IN record（84 字节）。USB 双向记录为整次调用的 OUT 与 IN 记录之和。 [USB 记录编码](../../runtime/UsbRecordCodec.cpp)

下表按一次完整调用累计。设 `A` 为计算启动批次数，`X` 为输入 Cache 写入次数，`Q` 为权重刷写次数，`M` 为回读选择批次数，`R` 为响应包数。设 `C`、`G`、`S`、`P` 分别为返回路由、启动指令、回读选择和 Cache 读请求的 flit 数。旧 BF16 路径另计 `I` 批 Idle 与 `J` 条 Idle flit。

| 发送步骤 | Host 下发批次 | USB OUT record |
| --- | ---: | ---: |
| 设置返回路由 | `A` | `C` |
| 选择计算用 Macro 并配置权重指数 | `X` | `4X` |
| 写入输入 Cache | `X` | `17X` |
| 刷写权重 | `Q` | `257Q` |
| 启动计算 | `A` | `G` |
| 发送 Idle | `I` | `J` |
| 下发回读选择 | `M` | `S` |
| 下发 Cache 读请求 | `M` | `P` |

前四步组成配置批次，其中包括实际刷写的权重。回读选择和读请求组成回读下发。接收侧单独统计 `R` 个响应包和 `7R` 条 IN record。

逐目标、全量刷写基线使用 `M=S=P=R`、`Q=X`。当前运行时按非空 Macro 批次统计 `M`，根据实际目标覆盖和路由统计 `S`、`P`。驻留命中省去 1 批权重刷写、257 条 OUT record 和 1 次权重写后等待。 [USB 调度](design.md#按-macro-批量回读) · [驻留规则](design.md#驻留身份与生命周期)

### 耗时分项

```text
单次调用耗时 ≈ 主机组织命令与整理结果 + USB 发送与接收 + 板卡固定等待

板卡固定等待 = 输入 Cache 写入次数 × 输入 Cache 写后等待
             + 权重刷写次数 × 权重写后等待
             + 计算启动批次数 × 计算及输出 Cache 写回等待
             + 回读选择批次数 × 回读选择后等待
```

| 分项 | 计入的阶段 |
| --- | --- |
| 主机组织命令与整理结果 | 打包输入和命令，解析响应，按输出绑定恢复结果 |
| USB 发送与接收 | 发送各类指令与数据，接收并收齐输出响应 |
| 输入 Cache 写后等待 | 输入 Cache 数据包发完后，等待写入完成 |
| 权重写后等待 | 权重数据包发完后，等待刷写完成 |
| 计算及输出 Cache 写回等待 | 整批启动指令发完后，等待计算及输出 Cache 写回 |
| 回读选择后等待 | 整批回读选择指令发完后，等待选择生效再发送读请求 |

设备打开和启动后的链路稳定按会话计。PLL 串口开销单独计量，次数取决于实际配置及切换。公式用于分项预算，实际耗时取决于等待配置、链路、主机处理及可重叠程度。比较编译方案时先核对各项操作次数及响应完整性。

## 基准条件

基线用干净的提交 `373ed03` 独立构建，采用该版本生产 Python 入口的逐列策略（`max-kernel-columns=1`）。按该版本的板卡控制规则，每次逐目标回读、全量刷写权重，BF16 每次启动后另发 Idle。当前组用性能工作树的编译器默认设置，启用自动列宽、FC/Linear 重排、按 Macro 批量回读、权重驻留和省略 Idle。

两组用同一份 Linalg IR、权重及形状重新生成 packet IR。每张表对应一次完整调用，权重槽从空状态开始。启动批次、输入 Cache 写入、启动指令和逻辑回读由编译制品及静态 Host 调用和循环展开取得。刷写、Host 发送批次和 USB record 由调用顺序、制品绑定和各版本运行时规则推导。完整 DVS 的当前组另外验证了启用重排前后的设备模块逐字节相同，用同一份设备绑定按重排后的 Host 调用顺序回放驻留。

## 单算子：Conv 与 MatMul

矩阵乘使用权重 `[N,K]` 左乘输入。两个卷积使用独立设计的尺寸。BF16 分组卷积输入和输出采用 NGCHW，权重采用 GFCHW。INT8 步长卷积输入和输出采用 NCHW，权重采用 FCHW。每个空间属性的标量值同时应用于高、宽两轴，padding 表示每侧补零数。

| 类型 | 算子 | 输入 → 输出 | 权重或卷积属性 | CIM K×N |
| --- | --- | --- | --- | ---: |
| Conv | BF16 分组空洞卷积 | `[1,3,3,7,11] → [1,3,6,7,11]` | `[3,6,3,3,3]`，3×3，stride=1，dilation=2，padding=2，groups=3 | 每组 27×6 |
| Conv | INT8 步长卷积 | `[1,8,13,17] → [1,19,7,9]` | `[19,8,3,3]`，3×3，stride=2，dilation=1，padding=1，groups=1，INT32 输出 | 72×19 |
| MatMul | BF16 65 列 MatMul | `[65,65] → [17,65]` | `[17,65]`，K/N/列数均有尾块 | 65×17 |
| MatMul | INT8 三列 Linear | `[256,3] → [320,3]` | `[320,256]`，INT32 输出 | 256×320 |
| MatVec | BF16 FC1 | `[256] → [512]` | `[512,256]` | 256×512 |
| MatVec | BF16 FC2 | `[512] → [110]` | `[110,512]` | 512×110 |

## Host 内存里程碑

完整 DVS T=32 样本采用固定 32 列、原 FC/Linear 调度和 Linux Release 模拟器。对照冻结基线与启用 Host 提前释放及 LIF 切片写入的原生制品。阶段峰值采用 Linux 进程 RSS，首次和重复推理的 25 个输出与状态哈希均一致。

| 推理阶段 | 冻结基线峰值 RSS | 优化后峰值 RSS |
| --- | ---: | ---: |
| 首次 | 5,610.59 MiB | 698.37 MiB |
| 重复 | 5,604.81 MiB | 790.35 MiB |

自动列宽相对固定 32 列的代价另行评估。完整 DVS 单样本在关闭 FC/Linear 重排的对照中，计算启动由 699,126 批降至 559,676 批，模拟器权重刷写由 36,256 次升至 40,048 次，原生编译所在 cgroup 的内存峰值由 4.32 GiB 升至 5.56 GiB。
