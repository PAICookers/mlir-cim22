# CIM 优化设计与验收

## 编译与软件执行

### 列块化与计算合批

归一化后的内核按列生成独立计算。设内积维度为 `K`，输出通道数为 `N`，列数为 `C`。每列的计算 tile 数 `t = ceil(K/64) × ceil(N/16)`，一波最多部署到 40 个 Macro。对列块宽度 `B`，每个归一化内核的波次数为：

```text
floor(C / B) × ceil(B × t / 40) + ceil((C mod B) × t / 40)
```

默认 `max-kernel-columns=auto` 在 1～40 列之间选宽。只有波次数少于固定 32 列时才替换。同波次数优先采用静态 tile 较少的方案。完整块复用模板，尾块按实际列数生成。两模板合计最多比固定 32 列额外展开 40 个 tile，单列超过 40 个 tile 时沿用固定宽度。BF16 各符号分支分别计数。显式 `=32` 保留固定列宽，`=1` 用于逐列对照。

同波的独立计算共享启动批次，逐列保留输入、权重、物理位置与输出绑定。变换保持 BF16 sign-split、K 分组、FP32 归约和舍入顺序，以及 INT8 累加语义。LIF、残差、池化、状态更新和 Host 后处理形成调度边界。计算启动和收包约束见 [USB 运行时](#usb-运行时)。

### 模型加载与原生编译

原生编译按资源所属函数索引设备操作，在拆分计算波次时原地更新包归属。生成单个 transaction 时按原序取出所需设备操作。生成制品前，先在设备数据完成解码后释放设备 IR，再在 LLVM IR 生成后释放 Host MLIR。Host 控制流转换按函数执行，限制同时存活的转换状态。

模型加载先验证制品，再逐个解码并释放已消费的序列化 transaction。静态执行计划和驻留身份在首次使用时准备，借用数据的计划须在制品数据之前销毁。

### 模拟器状态与静态绑定

首次执行时解析静态输入、权重、读回绑定及包位置，后续复用。为实际参与计算的 Macro 按需分配输出 Cache 状态。动态输入和数值准备按次更新，跨次保留的权重由 [驻留规则](#驻留身份与生命周期)管理。驻留计算直接读取槽内权重。

生产 Session 的输入与输出区域互不重叠，可以按 Macro 批量发布结果。直接 C++ 调用允许缓冲区共享，遵循原有 group 与回读顺序，保持后续读取可见的写入顺序。

[软件执行器](../../lib/Execution/CIMSoftwareRunner.cpp)

### Host 缓冲区与 LIF 切片

在所有权缓冲区释放处理后、结构化循环降级前运行提前释放优化。只对能排除堆缓冲区地址逃逸的 Host IR 启用。遇到显式取地址或向不透明函数传递堆缓冲区，保留所有权释放顺序。生成的 CIM 调度 wrapper 使用数值栈暂存区。

LIF 等时间栈中的静态单索引写入可从 `aten.select_scatter` 降到单步 `aten.slice_scatter` 和 `tensor.insert_slice`。先验证索引、形状及类型，不符合条件时沿用原分解。目标和源均可证明非负时，切片插入保持非负性，可供 BF16 符号分析使用。

[Host 降级](../../lib/Compiler/Pipelines.cpp) · [PyTorch 分解](../../python/cim22/backend.py)

### 跨算子融合边界

Depthwise 与 Pointwise 合并后，权重可能超出 INT8 可表示范围，稠密程度也可能增加。采用融合前须证明量化和 Host 后处理等价，评估 BF16 补偿与数值误差，并验证中间结果的状态与数据依赖。资源评估同时计入新增权重传输和槽位占用。

## USB 运行时

### 计算启动与写回屏障

板卡程序先完成参与 Core/Macro 的配置，再将独立 Core 的 WorkOnce 指令放入一个启动批次。Once 模式自动结束。INT8/BF16 普通推理及 BF16 原始采集共用此启动方式。整批启动指令发送完成后等待计算及输出 Cache 写回，再进入回读选择。一次计算的两个 Macro 结果由两个回读批次收集。

### 按 Macro 批量回读

响应头的 `[22:18]` 为 Core 来源索引，`[17:14]` 为 Cache 地址。Macro 编号由 Host 当前选择提供。包内保持顺序，不同 Core 的响应可乱序。回读流程如下。

1. 配置活动 Core 的返回路径和唯一来源索引，建立逻辑输出绑定。
2. 选择本批参与 Core 上同一编号的 Macro，按批等待选择生效。
3. 发送本批所需的 Cache 请求。同一地址覆盖全部 20 个规范路由的 Core 时可广播，其余目标按实际路由发送。广播选择还要求各 Core 使用同一数据模式。
4. 按逻辑 USB 通道重组响应，再按当前 Macro 批次、Core 索引和 Cache 地址归档。校验预期集合、重复包、响应格式和完整性。普通推理同时校验响应体填充位。
5. 收齐本批全部结果后才切换 Macro。最后按制品绑定恢复结果顺序。

全阵列 20 核、每核两个 Macro、每 Macro 八行时，两个批次共发送 16 条广播读请求，接收 320 个响应包。每包包含 1 条头 flit 和 6 条正文 flit。稀疏回读按实际期望集合验收。异常使设备进入故障状态并停止后续批次。原始采集保留响应体供诊断，同时执行包归属和完整性检查。

### PLL 状态复用

设备保存最近一次回显验证成功的 PLL 字。配置、计算和回读阶段需要相同字时复用，需要异频时执行切换并重新验证。关闭、重新打开、设备故障或无法验证当前串口时清除已验证状态。计算与回读的板卡等待仍按[成本模型](operation-counts.md#耗时分项)分别计入。

## 权重驻留与 FC/Linear 重排

### 驻留身份与生命周期

模拟器与 USB 共享身份规则，各自维护会话级物理槽位表。CIM22 有 20 个 Core，每个 Core 有两个 Macro。对同一槽位，只有权重身份和补偿模式都匹配时才命中。权重身份包括打包字、解码 mantissa、原始指数、路由和数据类型。首次使用时精确去重，哈希仅用于缩小比较范围。

| 路径 | 命中时 | 更新与失效 |
| --- | --- | --- |
| 模拟器 | 直接读取驻留 mantissa 与指数，按本次输入重新计算 | 冷槽或换权重时装载。调用失败清空驻留表 |
| USB 普通执行 | 省去 Weight 数据包及其写后等待 | 批次响应验证完成后确认候选状态。发送或协议异常、后续解码失败、关闭或重开使驻留状态失效 |
| USB 原始采集 | 全量刷写 | 使驻留状态失效 |

命中时仍执行 Macro 选择、Weight_EXP、输入 Cache 写入、启动计算和输出回读。INT8 保持有符号 INT21 检查和 INT32 累加。BF16 保持原始指数恢复、补偿及符号分支语义。输入和输出 Cache 依照执行边界更新。

### FC/Linear 批次重排

静态 Linear 在卷积规范化前标记来源。划分批次后，以完整的物理槽位及权重身份签名进行稳定分组，让同槽同权重的独立批次相邻。只在同一算子的合法直线区段内移动批次，输入必须可提前准备，结果必须保留原绑定。依赖、副作用及循环边界保持原序。

- INT8 多列 Linear 可把不同输入列的同权重批次相邻排列。
- BF16 配对可共享权重 tile 的 sign-split 分支，分别保存部分结果。原 FP32 归约、符号合成与舍入顺序保持不变。配对在私有 Host 函数中降低。
- 卷积使用现有列循环产生的驻留机会。

## 验收范围

| 验证层级 | 用途 |
| --- | --- |
| 制品静态展开 | 核对启动、配置、回读、绑定和传输记录数 |
| 独立软件参考与生产模拟器 | 核对数值、逻辑输出顺序、状态、别名及重复调用 |
| USB 和串口设备替身 | 核对发包顺序、等待、回包完整性、错误传播和状态失效 |
| 真实 USB 板卡 | 核对目标固件和时钟下的协议、数值及耗时 |
| 整网样本 | 在对应执行后端验证完整输出、模型状态及任务指标 |

每项结果应注明所用层级。性能对照使用相同输入、权重和计数口径，记录两组版本和生效选项。报告制品绑定与相关操作数，硬件耗时使用板卡测量。跨层结论需有对应层级的证据。

### 编译与模拟器

- 覆盖独立列、多核、尾块和重复输入，核对独立数值参考、原输出绑定及状态更新。
- 变更缓冲区生命周期时，验证已知的最后使用点、地址逃逸回退和输入输出共享。
- 验证默认 BF16 补偿和 INT8 各自的数值契约。 [BF16 数值说明](../BF16.md)

### USB 启动与回读

- 用不同 Core 的可区分结果覆盖乱序、分片及两个 Macro 连续回读。
- 注入重复、缺失、异常地址、半包及超时。普通推理同时验证响应体格式。异常在当前批次失败，后续 Macro 选择停止。需要复测时先确认设备已恢复。
- 核对整批启动后仍有计算和 Cache 写回等待。覆盖 PLL 同频复用、变频、回显失败及重新打开设备。
- 实板验收从有界代表算子开始，对照 INT8 和默认补偿 BF16 的软件参考，再扩展整网。

### 权重驻留与重排验收

- 两种模式均覆盖冷槽装载、换输入命中、换权重或换槽后重刷，以及故障或重开。BF16 另覆盖指数与补偿模式变化。
- 设备替身检查命中时省略 Weight 包和写后等待，原始采集全量刷写。
- 调度前后核对输出绑定、启动次数、回读数和数值。对完整模型分别标注静态重放、原生制品执行及实板验证结果。
