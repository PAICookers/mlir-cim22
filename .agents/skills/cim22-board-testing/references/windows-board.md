# Windows 实板与 USB

与[测试流程](workflow.md)配合使用。以下是已实测的 Windows 路径和诊断方法。
端点、串口、接口、请求大小和实现细节以当前硬件和实际加载的版本为准。

## 枚举、工具与时钟

- 用 `Get-PnpDevice -PresentOnly` 核对 Cypress FX3、UART 和 FPGA JTAG 的实例标识。
  从当前 CyAPI 枚举或 USB 描述符确认 VID/PID、接口与备用设置、Bulk OUT/IN、
  总线速度和端点参数。以前的 `04b4:00f1`、`0x01/0x81` 只是核对线索。当前
  CyAPI 运行时支持按设备地址消除歧义。地址会变，Linux 的 bus number 在 Windows
  路径不适用。会默认打开首个设备的供应方工具应先确认选中的就是目标设备。
  排除 Control Center、Streamer、供应方 GUI 和其他测试进程占用，保持单一 USB 执行者。
- 优先复用同提交、带 USB 的 Windows 构建并核对实际加载 DLL。工程 win_amd64
  运行时需要匹配的 x64 CyAPI 头文件与库。已验证的供应方包附带 x86 库时，用
  Win32 工具链编译观察版。遇到旧 CRT 或 Win32 符号链接错误，按供应方构建配置
  核对 CRT 与依赖，避免把编译失败当成驱动故障。供应方原件只读。
- CH340 等串口重新枚举后 COM 号可能变化。排除串口终端占用，使用当前
  `PLLConfig` 或 `clock_frequency_mhz` 配合 `pll_port`。采用运行时支持的
  PySerial 与 PLL 表，记录每阶段是新发并匹配回显、复用已验证的同一命令，
  还是仅发送。回显可分片，须按完整命令比对。物理频率与锁定状态由测量确认。

## Bulk 收发与会话收尾

- 首个 OUT 前，在实际使用的同一会话挂起 IN 并做有界空闲检查。收到意外数据时
  保存原始字节和状态，停在 OUT 前。FPGA 计数归零和 FIFO 空闲时，FX3 端点仍
  可能有遗留数据。区分 FPGA 编程、CIM 复位、FX3 断电和 USB 重枚举的实际范围。
- 已验证的 32 位供应方 chip-test 和 Windows 工程运行时使用最多 512 B 的
  Bulk OUT 请求。12 B 记录可跨请求边界，保持连续字节流。分别记录应用 OUT
  请求长度、CyAPI IN 请求长度、端点包长与 burst，以及已知的 FX3 DMA 缓冲设置。
  例如已测版本中，供应方异步 IN 默认请求为 512 KiB，工程运行时为 32 KiB。
  配置和比较应以实际版本为准。
- 记录成功完成的 TX/RX、请求与完成长度、出错 API、`NTSTATUS` 和
  `USBD_STATUS`。同一次请求的等待轮询超时可以只是尚未完成。运行中出现
  `FinishDataXfer` 失败，即使状态为 `0xc0000120` 或 `0xc0010000`，
  也应按传输故障处理。即便最后一批预期回包已完整落盘，仍要单列调用和关闭
  状态。仅在主动停止且与运行时预期取消路径吻合时，才接受取消完成。
- 收尾确认挂起的 IN 已完成或取消并回收，保存仍有效的尾数据，再释放句柄。
  若驱动未交还异步缓冲所有权，按实际运行时的隔离与恢复流程处理。普通正常
  关闭后可用新会话重验空闲。故障后按证据决定恢复范围，避免自动重发、清端点
  或复位。下一档的条件见[时序调优](timing-tuning.md#失败后能否换档)。

## FPGA 与 FX3 回环

- 先确认当前下载的是回环还是原 CIM 桥接镜像，并匹配对应 LTX、核和探针。
  用 Vivado Lab 或兼容工具串行采集，优先使用已有 hw_server。刷新并核对
  实际探针字段，采集前确认 ILA 空闲。按需要记录 VIO 的当前值，并在结束时
  回收本次采集。回环的活动速率窗口与原桥接的累计计数器采用各自语义。
- 回环可从短记录和按生产分块的已知字节流入手，比较完整 TX/RX。已实测的
  供应方 10,020 B 流按 512 B 分块并带短尾时逐字节匹配。3072 B 负载曾在
  大 IN 请求下超时，复位后以 6×512 B OUT 加精确 3072 B IN 回读成功。
  该对照同时改变了恢复状态和 IN 请求大小。若要定位满包边界，固定载荷、
  OUT 分块和初始状态，分别比较精确长度与大 IN 请求，配合尾拍
  `SLWR#`/`PKTEND#` 采集。OUT 完成、GPIF 有活动、Host IN 完成分别取证。
- 回环通过覆盖当前镜像、负载与请求组合下的 Host↔FX3↔FPGA。恢复原 CIM
  桥接后重新核对空闲、送达和数值。若桥接发送 FIFO 有残留且 FPGA→CIM
  `req/ack` 持续不匹配，优先看该接口握手。若 FPGA 回传和 GPIF 写计数
  都未增加，则记录回包尚未进入 USB 回传路径的观测范围。更换 CIM 板卡及
  重新插接后的结果按实际更改记录，单次对照不足以区分板卡本体与连接问题。
