## 配置默认值与覆盖方式

当前默认目标是 **128 MHz**，五项等待为 **20/0/0/0/2 ms**。这组配置在实板上连续
通过 512 个事务的逐位比较。使用其他板卡、镜像或供电条件时，按本页重新验证。

| `CIMTimingConfig` 字段 | 默认 ms | 生效时机 |
| --- | ---: | --- |
| `startup_delay_ms` | 20 | USB 会话打开后 |
| `cache_write_delay_ms` | 0 | 每次输入 Cache 写入后 |
| `weight_write_delay_ms` | 0 | 每次实际权重写入后 |
| `work_delay_ms` | 0 | 一批 WorkOnce 发送后 |
| `readback_select_delay_ms` | 2 | 读回前选择 Macro 后 |

- 自动设钟时给 `UsbConfig.pll_port` 填实际串口，Windows 使用 COM 端口名，Linux
  使用设备路径。由运行时通过 PLL 表配置写入、计算和读回阶段。用
  `clock_frequency_mhz` 覆盖默认频率。请求不在表中时，选择最近的可用表项，平距取较低项，
  并通过警告报告实际选择。分阶段设钟时使用 `UsbConfig.pll`，填入带 `port`、
  `config_hex`、`work_hex`、`readback_hex` 的 `PLLConfig`，
  并省略 `pll_port` 和 `clock_frequency_mhz`。三阶段的十六进制字应来自当前板卡已确认的 PLL 表。
- 手动设钟时省略 `pll_port` 和 `pll`，按板卡 PLL 操作说明先设置目标频率，再开始 USB 执行。
  当前 Web 表单可调整等待，使用手动设钟。Vivado 的 `refresh_hw_device` 只刷新调试视图。
- 串口首次指令需要匹配回显，后续命令沿用运行时的同步发送流程。记录实际应用的表项、
  回显及各阶段频率。回显确认了串口通信，物理频率和锁定状态由现场测量确认。
  配置前释放会抢读回显的串口终端。
- Python 通过 `UsbConfig(timing=CIMTimingConfig(...))` 覆盖等待，省略的字段沿用默认值。
  实板 pytest 的 `--board-config` 使用相同字段，等待放在 JSON 的 `timing` 对象内。
  USB 轮询间隔和回包期限各自独立于这五项等待。

以下 **24 MHz / 20/1/2/40/100 ms** 保守档也经过实板验证。可用于换板或时序诊断。
在基于频率表或手动设钟的 USB 配置上覆盖如下。手动路径同步把板卡设为 24 MHz。

```python
from dataclasses import replace

from cim22 import CIMTimingConfig

conservative = replace(
    config,
    clock_frequency_mhz=24,
    timing=CIMTimingConfig(
        startup_delay_ms=20,
        cache_write_delay_ms=1,
        weight_write_delay_ms=2,
        work_delay_ms=40,
        readback_select_delay_ms=100,
    ),
)
```

## 逐档验证

1. 从当前板卡已验证的组合开始。核对源码中实际生效的时序以及默认值与本轮覆盖值，
   固定输入、权重、编译制品、运行时、固件、传输分块和采集方法。为每档记录请求频率、
   PLL 选中表项、串口回显、配置/Work/读回各阶段频率和五项等待。优先用当前版本的
   PLL 查表规则。供应方表中的 `available` 是候选资格，稳定性由本轮数值与协议验证，
   物理频率由测量确认。
2. 要判断某项变化的贡献时，一次改一项。升频可先保留已验证的等待；缩短等待可先固定
   频率。用户指定同时改多项时按组合测试，性能或错误只归属于该组合。优先看等待的
   调用次数和总预算。启动通常每会话一次，Cache 写后等待按写入次数累积，权重写后
   等待只随实际写入发生。Work 和选宏分别按事务与读回批次累积。同一事务可能有多批
   选宏读回。升频只直接改变随 CIM 时钟计数的阶段，Host 毫秒级等待依然按设置执行。
3. **每档先跑供应方用例。** 按[当前环境](workflow.md#定位当前环境)定位已交付的
   32 位供应方包，选择其中的 `int8_0p5_20cores` 及同版本参考。
   从供应方交付的版本清单定位用例及参考数据。供应方入口
   缺少所需时序选项时，在本地观察版调整对应的等待和 PLL 设置，保留原件、编帧、
   分组和读回顺序。核对实际执行的等待点，记录供应方与工程路径的启动、分批和等待
   差异。验收配置送达、完整有效的回包和全部 Cache 计算结果。对已知权重读回缺陷，
   保留读回及协议检查并单列数值结果；若程序仅因已知的权重数值差异退出失败，
   以完整证据核实其余验收项后仍可放行。供应方用例缺失时报告前置验证缺项。
4. **供应方前测通过后，再跑编译器用例。** 优先检查当前版本的 `python/tests/board`
   或同等入口。选能区分单/多 Macro、单/多核、单/多事务的用例，按实际制品核对
   放置和动态 dispatch。计时沿用相同的代表性算子与输入，先预热再重复测量。
   同时保存数值对照。一个小算子成功只说明它所覆盖的路径。

5. **换档前刷新设备。** 结束本档并关闭 USB、串口及本轮 ILA 采集后，若现场确认无需
   硬件复位，在应用下一组频率或时延前，按 [Vivado Lab 换档步骤](vivado-lab.md#收尾与换档)对当前 FPGA 执行
   `refresh_hw_device`。本档通过或失败均按上述条件处理。可在本档结束时完成刷新，
   或在下一档首次下发前完成。保存刷新日志及刷新后的新鲜 ILA 空闲采样，并在新会话
   中重做空闲 IN。Refresh 只更新 Vivado 的器件和探针状态，恢复仍以现场检查为准。

## 失败后能否换档

- **仅数值失败时可换档。** 收齐当前有界回包，保留原始位型与差异坐标，结束该档并
  正常关闭会话。若传输和协议通过、运行时无故障，且新鲜观测确认 FIFO 空闲、握手匹配、
  计数与本轮收发一致，便可在已授权的范围内继续下一档，无需为单纯的数值不匹配复位。
  新档重新核对设备与空闲状态，在实际发送的同一 USB 句柄上完成空闲 IN 检查，
  并从供应方用例重新开始。保存各档独立结果。
- **传输、协议或送达失败时停止新 OUT。** 保留完成前缀和状态码。运行中出现 IN 错误、
  超时、缺包、意外空闲 IN、握手卡住或关闭故障时，先排查受影响的环节并验证恢复，
  再用新会话重做空闲与送达检查。完整回包与 IN 完成错误可以同时发生，按实际错误和
  清理状态处理。恢复步骤由现场证据决定，见[硬件排障](hardware-recovery.md#按观测定位与恢复)。

## 实测耗时和模型估算

算子计时使用预热后的同一 Session 调用，记录样本数、中位数和范围。编译、USB 会话
建立和预热单列；若包含 ILA 同步放行，保留原始耗时并逐次扣除实测阻塞时间。调整后的
Session 时间仍含 USB、配置、运行时等待、读回和 Host 运算。要分别量写入、Work 到
完成、选宏、发读请求到收齐结果，使用对应的时间戳或硬件完成观测，明确事件边界。
没有芯片完成信号或可验证的周期模型时，报告端到端实测与固定等待估算。

用实际编译制品的事务和放置计划统计操作数。对整网展开 Host 循环和间接调用，尽可能
用同一模型的实际动态 dispatch 核对。多时间步模型按一个完整样本统计。
从传输记录或运行时计数核对实际权重重写次数、读回批次及 TX/RX 字节数。按实测或
可验证的驻留策略估计重写次数；缺少证据时给出全命中到全重写的预算区间，并注明
冷启动的首次权重装载是否单列。

```text
固定等待（ms） =
    USB 会话打开次数 × 启动等待
  + 输入 Cache 写入次数 × Cache 写后等待
  + 实际权重写入次数 × 权重写后等待
  + WorkOnce 批次数 × Work 后等待
  + 读回选宏批次数 × 选宏后等待
```

按当前运行时实际插入等待的位置核对各项计数。一个事务若把多个核的 WorkOnce 合成
一次发送后只等待一次，就按一批计算。权重写的 USB 分块只增加传输调用数，写后等待
按完整写操作计。固定等待除以 3,600,000 得小时，除以同口径实测总耗时可估算其占比。
这个预算采用配置值，实际 Host 休眠可能更长。

有可靠周期计数时，单个顺序计算阶段的芯片耗时为 `周期数 / (频率 MHz × 1000)` ms。
并行核或 Macro 按关键路径计周期，串行批次再累加。只有在确认同一操作的周期数及并行度
保持一致时，才按旧频率与新频率之比缩放这部分。估算整网端到端时，可按相似事务的
实测范围估计 USB 传输、Host 运算及超额等待，优先使用已分段测量的值。Work 固定等待
期间若已覆盖芯片执行，只加等待窗口之外的部分；直接外推端到端样本时也避免再次
叠加其已包含的等待和传输。缺少可外推的数据时给出固定等待下界；未完整通过实板的
组合只给条件估算，并区分整网实测与估算。

例如，某算子执行 4 批 WorkOnce、8 批选宏读回、16 次 Cache 写和 16 次权重写。
若会话已打开，Work/选宏为 10/40 ms、两项写等待各 1 ms，名义固定等待为
`4×10 + 8×40 + 16×1 + 16×1 = 392 ms`。把选宏改为 30 ms 时，预算减少
`8×(40−30) = 80 ms`。整网用展开后的每样本计数做相同计算。
