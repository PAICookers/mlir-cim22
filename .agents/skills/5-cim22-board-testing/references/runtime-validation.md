## 保持实际执行路径

- 使用同一编译产物、同一输入，分别运行生产软件runner与USB/BoardRunner。
  核对真实权重、指数、映射、Cache行和计划字节，不手工重建transaction替换产物。
- 在当前检出的测试或已安装工具中定位执行入口，并核对配套构建。
- 执行工具前核对当前版本实际支持的参数/dtype，`--help`/`--list`并非所有工具都有。
  只读规划仅定位入口，不启动执行器。缺少某个harness时先评估现有测试/runner接口
  能覆盖的范围；报告缺失入口，不伪造命令或通过。默认离线测试不能悄悄切到USB。
- 正式模型支持时用现有 `torch.compile`/运行时入口；尚只支持原生typed transaction
  的dtype，不虚构公共ABI或以供应方runner代替生产链验收。
- 实际Host IR的切片、归约、拼接和裁尾也要执行并核对。仅在device边界回放实板
  数据时标为Host回放；手工组装完整调度时标明编译器实际生成了哪些片段。

## 数值参考

| 数据类型/环节 | 比较方式 |
| --- | --- |
| INT8 | 独立宽整数dot、signed21范围/解码及最终Host累加；最终结果可超出单tile的21bit范围 |
| BF16软件模拟 | 预对齐→整数MAC→`int21ToBF16(sum,Ew[lane],Ei)`，模拟芯片内部转换 |
| BF16实板读回 | 21bit槽是容器，取低16bit；不再做指数重建，不要求槽高5bit必须为0 |
| BF16差分 | 在Host浮点扩展之前比较原始16bit，保留NaN/Inf位型；协议/padding仍需独立检查 |

原始BF16位型按无符号16bit或整数bitcast处理；测试辅助代码生成常量时也应保留
全部位，不能把符号位为1的原始位型作为超范围的有符号正数，触发检查器自身断言。

本技能采用的CIM22 BF16项目参考约定如下；核对当前代码/板卡版本是否采用兼容约定。
它来源于项目已采纳的供应方Python模型，不要求接收方持有原始脚本或私有笔记：

- 对64元素行取原始8bit指数字段最大值Emax。norm补隐藏位1，denorm补0；norm的
  d=Emax-E，denorm的d=Emax-1。负数先将8bit尾数转为补码。
- d<7时对该8bit值逻辑右移d+1，再加sign<<7并截为8bit；d>=7时置零。
  全denorm时d=-1、移位量0，保留该参考行为。权重逐输出lane独立处理64个值。
- 整数MAC得到S后，非零值取shift=floor(log2(abs(S)))-7，零取shift=0；abs(S)
  在shift>=0时右移shift，否则左移-shift，取结果低7bit作fraction；指数将
  Ew+Ei+1+shift夹断到[0,255]并拼接符号。
  零也走该指数路径；指数255保留Inf/NaN位型，不擅自改成普通IEEE运算。
- 预处理与该参考对应即可按项目参考一致性验收，不另设硬件或golden前置证明。
  当前有限输入支持域及拒绝规则以接收方版本为准；不同协议/芯片版本不可直接套用。

若原供应方数据不可用，可构造确定性、可区分的数据比较两种runner，并按上述约定
建立参考。没有独立oracle时如实只报告两端一致性；不要声称重新对照了缺失的原件。

两种runner共用编译阶段生成的准备权重/指数；两端一致可验证已编码数据的实际执行，
不自动成为普通PyTorch数学等价证明。若任务明确要求数学等价，另列该参考与结果；
不能因参考模型产生NaN/Inf就改算法，也不能把这些位型直接当成USB故障。原始位型
与最终Host输出分开检查，后者遵循实际Host转换/归约语义。可按当前版本的数值契约进一步核对。

## BF16 Host 归约与判别用例

先核对当前编译器生成的Host IR，再选择参考归约。已验证的CIM22路径在多K时
将每个BF16 partial扩展为FP32，按K源顺序依次累加，最后只做一次BF16舍入；
单K直接使用该partial。不能用逐步BF16相加、无序sum或重写的Host算法替代原IR。
分别接回软件/USB的partial，执行原切片、padding、归约、拼接和裁尾，检查最终
整数位型。Host回放覆盖上述算术，不自动覆盖公开Session的dispatch/ABI。

对具有上述FP32归约和最终ties-to-even语义的版本，可用以下独立反例核查用例
是否真能识别错误；它们是构造思路，不依赖某套TB、历史回包或固定测试文件：

- `[2^27, 2^-23, -2^27]` 按源顺序FP32累加得到0；先抵消第一、三项再加第二项
  得到 `2^-23`，可区分错误重排。
- `[1, 2^-8, 2^-8]` 累加后一次BF16舍入得到 `1.0078125`（`3f81`）；每步先舍入
  回BF16则得到1（`3f80`），可区分过早舍入。

必须检查实际软件/USB partial是否形成预期轨迹，不能只给case起“归约顺序”名字。
基础规模用例宜有混合符号、不同指数/尾数及可区分的有限输出；需要NaN/Inf覆盖时
另列位型用例，不把有限值规模通过算作非有限覆盖。Host浮点扩展可能改变NaN的
quiet/payload位，原始partial与最终Host位型分别验收。

## 覆盖矩阵

按当前实现和任务目标选用例，给每个实际执行的后端单独记录结果；不把历史或
软件通过填为本轮实板通过。各核、Macro和分块使用可区分数据，避免全零或重复
数据掩盖错路由、错宏、错行。必要分类如下，有共享数据表就复用，否则记录本轮
实际执行的用例参数。

| 分类 | 核查点 |
| --- | --- |
| 放置 | 同核双Macro、多核、全阵列、最后一个不满的核 |
| 几何 | M/N/K分块、K64边界、尾块补零与输出裁尾 |
| 数值 | 符号/边界、BF16指数差与位型、与所选参考一致性 |
| 执行 | 一个算子多次CIM、Host K归约、跨轮资源复用及Cache行复用 |
| 生命周期 | 同会话重复执行、独立打开/执行/关闭，无未经声明的中途恢复 |
| 算子链 | 若在任务范围，前一输出供后一输入及完整模型入口 |

资源复用必须让同一物理位置的下一轮准备权重word或指数实际变化；只改变原始
矩阵或依赖周期性生成公式不足以保证这一点。核对编码指纹和所用位置，防止漏写
旧数据仍能通过。由当前目标的容量确定规模及预期 Work 次数。

BF16尾块的输入/权重补零不意味着padding lane输出位型为0：上述参考的零点积
仍走指数路径。先比较完整物理结果槽，再核对原Host只保留有效N范围。

单tile或供应方固定向量通过只覆盖相应子集；INT8规模通过也不能替BF16填表。
只有“输入原始BF16权重并由编译器生成全部产物”的路径才覆盖这部分编译过程；
供应方准备权重、手工帧、离线double和Host回放分别标注边界。

## 检查有效性与收口

用独立参考核查布局/数值，至少保留与所改边界相关的有效负例，例如扰动一个返回值
使Host检查失败，或畸形包被拒绝；不把程序崩溃当作预期拒绝。避免镜像实现的断言
和与规模矩阵重复的弱测试，复用已有组件而非另造长期测试框架。

确认软件/计划检查通过后再执行授权的USB模式；每个Work门禁检查真实配置前缀和
当前观测。按回包完整性、部分结果、最终Host输出和关闭状态分别验收。新case尽量
归入项目正式测试与分类文档；技能只保留入口和方法，不复制原始fixture或最新PASS数。
